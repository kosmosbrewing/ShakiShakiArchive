## 요약

첫 로딩 전송량·첫 페인트 개선이 목표. 비로그인 첫 방문자가 받던 admin(178KB)+payment(163KB)
청크가 첫 로딩에서 제거되고, constants API 응답을 기다리던 흰 화면 구간이 사라짐.
배포 직후 stale 청크 404에 대한 자동 복구 가드가 추가되어 가용성이 향상됨.

## 변경 내역

### 1. 전 라우트 lazy import 전환 + 청크 로드 실패 리로드 가드 (`f355acd`)
- Home 외 36개 페이지를 개별 `.vue` lazy import로 전환, 배럴 파일(`pages/*/index.ts`) 10개 삭제
  (배럴 정적 import 재도입으로 lazy가 조용히 깨지는 회귀 방지)
- 배포 직후 옛 index.html 사용자의 lazy 청크 404 → sessionStorage 가드 기반 1회 전체 리로드

### 2. three.js 청크 분리 + manualChunks 구조 수정 (`ff0bced`)
- three(557KB)를 별도 청크로 — libs 639KB → 91KB, Home 청크에만 딸려감
- **버그 수정**: vendor 분기 `id.includes('vue')`가 radix-vue/lucide를 삼켜 ui 청크 분기가
  죽은 코드였음 → 경로 단위 매칭으로 수정, ui 청크(105KB) 실분리
- **구조 발견**: admin/payment 경로 그룹핑이 공유 모듈 64개(스토어·messages·ui)를 흡수해
  index가 payment를 정적 import(첫 로딩 preload)하던 Rollup 동작 확인 → 그룹핑 제거,
  라우트 lazy 기반 자연 분할로 전환. 상세 교훈은 메모리 `vite-manualchunks-pitfalls` 참조

### 3. constants 로드 mount-first 전환 (`37f81f4`)
- `await loadConstants()` 제거 — mount 먼저, constants는 백그라운드 (흰 화면 구간 제거)
- 소비처 전수(cart/validators/AdminCancelOrderModal)가 reactive 폴백 패턴이라 무손상
- `ensureLoaded()`(in-flight promise 공유) 신설, 결제 경로(Order.vue)만 완료 보장

### 4. 미사용 Hero.vue 삭제 (`6e8b359`)
- 구 이미지 슬라이더 삭제 (import처 0건). siteImage 스토어·관리자 화면은 유지

### 5. 리뷰 반영 수정 (`5b51add`)
- `vite:preloadError` 무가드 리로드 → `lib/chunkReload.ts`로 통합, 무한 리로드 루프 방지
- sessionStorage 접근 try/catch (스토리지 차단 환경에서 복구 핸들러가 죽던 문제)
- Order.vue의 ensureLoaded/loadUser 직렬 await 병렬화

### 6. S3 lifecycle 규칙 CI 코드화 (`8a91391`)
- deploy.yml에 assets/ 60일 만료 규칙 멱등 적용 스텝 추가
- ⚠️ **미완**: CI IAM 사용자(shakishaki-archive-frontend)에 `s3:PutLifecycleConfiguration`
  권한이 없어 경고로 스킵 중 — 권한 추가 후 자동 적용됨 (배포는 정상)
